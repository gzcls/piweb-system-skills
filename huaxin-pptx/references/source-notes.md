# 来源、整合与实施说明

版本：2.1.1。技能名为 `huaxin-pptx`（1.x 版本名为 `pptx`），品牌中文名为“华新”。
这是独立的 Agent Skills 目录包，不是 ChatGPT 模板库的安装卡，也不是插件市场的发布包。

## 用户提供的来源

2.1.1 增加共享输入预检和 `validate-spec` 命令，明确 `type`/`kind` 字段及多行脚本执行方式；预检不替代构建容量检查与逐页视觉检查。

| 来源 | 采用内容 | 在本包中的位置 |
| --- | --- | --- |
| `指令.md` | 角色、工作流程、只做必要追问、优先使用模板、首页标签、尾页、改版及质检要求 | `SKILL.md`、`references/quality-checklist.md` |
| `template-style-guide.md` | 配色、栅格、间距、字体、内容密度、卡片、图表、图片与页面规则 | `references/style-guide.md`、主题配置 |
| `huaxin-ppt-style(2).zip` | 原始模板、两张背景、原技能规则、展示配置 | `assets/`、`agents/openai.yaml` |

三项原始二进制素材按字节原样保留，SHA-256、像素尺寸和模板尺寸见资源清单。包中没有附带独立字体文件，也没有为原素材附加未经授权的开放许可证。

## 合并处理（1.x 起）
1. **尾页**：统一为答谢尾页使用首页背景。
2. **背景指向**：直接使用 `assets/` 中的图片，不再依赖“第二张参考图”这类隐式引用。
3. **去重**：视觉规范只保留一份。
4. **占位例外**：首页的汇报人和日期缺失时，允许保留可编辑字段。
5. **首页标签对比度**：首页右下角是白底，标签使用深灰蓝 `#445469`，不使用白字。

## 2.0.0 变更及原因

| 变更 | 原因 |
| --- | --- |
| 技能更名为 `huaxin-pptx` | `pptx` 是通用名称，又允许隐式调用，容易接管所有 PPT 任务；新的 description 写明了何时不使用本技能 |
| 只保留运行画布一套数值（10 × 5.625 英寸） | 设计基准与运行画布两套单位相互矛盾：设计基准下“正文 13 pt、图表 10 pt、脚注 9 pt”乘以 0.75 后，分别低于运行下限 11、10、8 pt。现在统一以运行下限为准，设计基准只保留在 style-guide 附录中用于追溯 |
| 新增 `scripts/hx_pptx.py`（克隆模板页 + 版式配方） | 1.x 把“编辑原模板副本”列为首选路径，却没有任何工具支撑，智能体只能临场摸索或退回背景图方案 |
| 新增 `references/template-map.md` | 模板文字是普通文本框而不是占位符，信息图多为组合图形；逐页索引可以避免每次运行都重新遍历模板 |
| 新增 `references/layouts.md` | 把“采用 12 栏栅格”这类原则改成预先算好的坐标、字数上限和命名规范 |
| 修复圆角 | 1.x 的 `create_starter.py` 没有设置 `adjustments[0]`，python-pptx 默认圆角约 0.253 英寸，超出 0.167 英寸上限；1.x 的校验器只检查配置，不读取形状的实际 `adj` |
| 校验器改为按页统计密度 | 1.x 把全稿的卡片、要点、图表总数与“每页”上限比较，长稿必然误报 |
| 校验器检查实际圆角、逐个形状的字号下限、更多模板残留文字 | 把规则落实为可以自动检测的项目 |
| 颜色 Token 对齐 | 1.x 配置中 `primary=44546A` 与规范 `#445469` 不一致，还混入了 `0F172A`、`ED7D31`、`E7E6E6`、`CBD5E1` 等规范外颜色；现在校验器要求配置中的每个颜色都写进 style-guide |
| 页脚 Token 改为“来源行” | 1.x 的页脚是蓝色实心条，并预留了页码位，与“不新增页码”“保留底部色带”的规则冲突 |
| 首页标签改为 9.75 pt | 原 8.25 pt 低于正文下限，会触发本包自己的检查提示；9.75 pt 仍在 8–10 pt 的标签范围内 |
| 视觉证据改为两步：先渲染，再 `--attest` | 1.x 允许在同一条命令中同时渲染并声明“已人工复核”，PNG 还没生成就已经背书 |
| 修复 Windows 下的渲染失败 | LibreOffice 配置目录清理时文件被占用，导致 `render_visual.py` 报错退出 |
| 删除 PptxGenJS 分支（`pptxgenjs.md`、`package.json`、`package-lock.json`） | 所有脚本和测试都基于 Python，JS 分支没有经过验证，并且 `pptxgenjs.md` 没有被 SKILL.md 引用 |
| 修正 `clean.py` 的描述 | 该脚本只删除 `.tmp` 和 `.bak` 文件，原文档称其能“清理未引用对象”，与事实不符 |

## 2.1.0 变更及原因（代码简化）

| 变更 | 原因 |
| --- | --- |
| 主题配置瘦身（schema v3）：删除阴影、`use_for`、图片规则、图表类型建议、与 `content_slide` 完全相同的 `toc/transition/summary_slide`、`bg_rules`、各类别名等字段 | 约 45% 的键没有被任何生成代码使用，只是重复 style-guide 中的文字规则；Schema 从 1046 行缩减到约 260 行，并禁止未知键 |
| 彻底删除设计画布（`design_canvas`、`runtime_scale`、`typography.design/ranges`、`create_starter --canvas design`） | 落实“只用一套单位”；校验器仍会按比例检查 13.333 英寸的旧稿 |
| 校验器只检查各字段之间是否一致（正文区与安全区、页脚线、字号与下限、间距取自节奏、颜色引用存在、圆角大小顺序） | 原来在校验器里重复写死 5/4/11/10/0.104–0.167 等数值，相当于两个事实来源 |
| 配方常量移入配置的 `recipes` 段；标题、副标题、目录、结论的字数上限改为由“文本框宽度 ÷ 字号”计算 | 2.0.0 在 `layouts.md` 中声称“只改配置即可”，但代码里还有约 27 处写死的常量 |
| 模板残留文字列表移入 `qa.template_markers` | 原来构建脚本和校验器各有一份，且已不一致 |
| `create_starter.py` 改为复用 `hx_pptx` 的辅助函数（从 426 行减到约 100 行） | 消除重复实现；起稿的卡片、标题、来源行与正式构建完全一致，中文字体也会写入东亚字体字段 |
| `hx_pptx.py`：去掉 `P["..."]` 间接调用；用 `BuildContext` / `Block` 数据类统一页面和配方的参数；spec 中的 `font` 通过 `use_font()` 作用于所有页面；尾页统一应用 `slides.closing.title` 几何框 | 消除未使用的参数和常量，修复字体覆盖不完整及原模板尾页文本框偏窄（3.49 英寸）偏右的问题 |
| `inspect_pptx` 拆出 `_inspect_slide`、`_off_slide_objects`，并覆盖不含 `HX_` 前缀的语义命名对象圆角检查 | 原函数约 250 行；补齐 `STEP` / `TAG` 等语义命名的圆角检测 |
| 新增测试：表格、双栏、图文、组合版式、模板文字/图表/表格替换、字体覆盖、起稿脚本、13.333 英寸旧稿缩放检查，以及不依赖 LibreOffice 的视觉证据测试 | 2.0.0 中这些路径缺少自动化回归覆盖 |

重构前后，用同一份示例 spec（8 页）和全配方 spec（13 页）构建并渲染：除 2 个尾页因修复为 `slides.closing.title` 居中而有预期位置校正外，其余 19 页 PNG 逐像素 100% 一致；回退起稿脚本的 3 页有预期变化（改用共享辅助函数和东亚字体）。

## 检查发现的事实
- 原始 PPTX 画布为 10 × 5.625 英寸；共 30 页、11 个版式、13 个媒体文件。
- 正文背景与模板内的 `ppt/media/image1.jpeg` 完全一致，首页背景与 `image2.jpeg` 完全一致，尺寸均为 3000 × 1689。
- 模板第 2、3 页各有一个隐藏的“02”文本框；第 22、23 页是原生图表；第 6、12、15 页含样张照片。
- 模板使用的字体为 PingFang SC 和思源黑体，没有嵌入；本包统一使用 Microsoft YaHei。
