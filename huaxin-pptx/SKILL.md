# 华新 PPTX 制作

## 1. 边界

- 只要用户没有明确表示仅需页纲或文案，就必须交付实际的 `.pptx` 文件。默认使用中文；用户指定其他语言时跟随。
- 用户指定其他品牌模板时，不使用本包的素材和视觉规则，最多借鉴流程与质检方法。
- 所有路径均相对于本 `SKILL.md` 所在目录。输出文件和临时文件必须放在技能目录**之外**；本包内的模板与背景只读。

## 2. 唯一坐标系（运行画布，所有数值均以此为准）

成品统一使用原模板画布 **10 × 5.625 英寸**。旧规范中 13.333 × 7.5 英寸的“设计基准”只用于追溯来源，**不得用于制作**。
以下数值以及所有配方常量都来自 [主题配置](scripts/office/huaxin_theme_config.json)（唯一来源）：

| 项 | 值 |
| --- | --- |
| 正文区 | x 0.50，y 0.84，w 9.00，h 4.18（底边 5.02） |
| 标题栏标题 | x 1.6725，y 0.094，w 6.975，h 0.41；白色粗体 22.5 pt，超过 22 字用 19.5 pt，超过 25 字须改写 |
| 左上章节标签 | x 0.50，y 0.09，w 0.68，h 0.44；只放 `01`、`02`、`目录` 这类短标签 |
| 来源行 | x 0.50，y 5.34，w 9.00，h 0.18；8 pt，`#445469`，只有文字，不加底色、不放页码 |
| 栅格 | 12 栏，栏间距 0.18；双栏宽 4.41，三栏宽 2.88，四栏宽 2.115（坐标见 [layouts.md](references/layouts.md)） |
| 字号 | 结论 18、卡片标题 13.5、正文 11.25、关键数字 25.5、图表 10、首页标题 28.5、首页副标题 14.25、首页标签 9.75、来源 8 pt |
| 字号下限 | 正文 11 pt，图表 10 pt，脚注、来源、标签 8 pt；放不下就压缩、重组或拆页，不得缩字 |
| 圆角 | 卡片、指标块、面板、图片框用 `ROUNDED_RECTANGLE`，半径 0.125 英寸（允许 0.104–0.167）；胶囊半径取 min(h/2, 0.167) |
| 颜色与字体 | 蓝紫 `#374B9B`，深灰蓝 `#445469`，强调红 `#E63237`（仅少量使用），正文 `#3E3A39`，面板底 `#F3F5F9`；字体 Microsoft YaHei |

python-pptx 的圆角比例**必须换算**：`shape.adjustments[0] = 半径 / min(宽, 高)`。直接用默认值会得到约 0.25 英寸的圆角，不合规。

## 4. 工作流程

### 4.1 判断任务并读取输入
先判断任务属于哪一类：新建、文档转稿、改版、局部续改、仅要文案。附件以实际内容为准，不凭文件名推测。
只追问会实质改变结果的信息（受众、用途、强制页数、必须保留的内容）；能合理推断的直接处理，并说明假设。
不要为汇报人或日期单独追问，缺失时保留 `汇报人｜汇报日期` 字段。
用户没有要求外部研究时，以用户材料为准，不补造事实或数字；涉及最新公开信息时先检索核实，并在来源行或备注中注明出处。

### 4.2 一次性确定页表
先输出页表，再动手制作：

```text
| # | 类型(cover/toc/section/content/template/closing) | 观点标题(≤22字) | 核心结论 | 版式配方 | 素材/数据来源 |
```

完整稿默认以首页开始、以答谢尾页结束，用户指定的总页数**包含**首尾页。页数未指定时，采用最短但完整的篇幅。
局部续改只处理指定的页面范围，不另加首页或尾页。

### 4.3 生成（首选：克隆原模板）
1. 先运行 `python scripts/hx_pptx.py example-spec` 读取完整示例，再按 [layouts.md](references/layouts.md) 写 spec JSON。版式块使用 `type`，图表使用 `type=chart` 与 `kind=doughnut/line/...`，不要猜测字段名。
2. 先运行 `python scripts/hx_pptx.py validate-spec --spec <spec.json>`；返回 `VALID` 后运行 `python scripts/hx_pptx.py build --spec <spec.json> --output <技能目录外>/<name>.pptx`。预检不写文件，只检查输入结构，布局容量仍由构建与质检验证。
   - 首页、目录、章节页、答谢页直接克隆原模板第 1、2、4、30 页，并按规则替换文字。首页右下角合并为一行 `汇报人｜汇报日期`。
   - 正文页使用模板正文版式，由配方生成原生文本、圆角卡片、表格和可编辑图表。
   - 想复用模板信息图页时，先运行 `python scripts/hx_pptx.py slots --slide N` 查看槽位，再用 `template` 类型逐槽替换文字。
   - 违反硬规则（超出字数、超出密度、放不下）时构建会**直接报错**。按提示压缩、重组或拆页，不要绕过。
3. 配方无法表达的页面，用库函数在同一份演示文稿上补画（见 [layouts.md](references/layouts.md) 第 5 节），对象命名遵循 `HX_*` 规范。
4. 回退路径：只有无法使用模板克隆时，才用 `scripts/create_starter.py` 生成以背景图起稿的未完成稿。这条路径不保留母版。

涉及循环、XML 修复或多行逻辑时，将代码写入工作区 `.py` 文件再执行；不要将字面量 `\n` 拼进 `python -c`。简单单行查询可使用 `python -c`。`prs.slides` 只按整数索引访问；选取范围使用 `list(prs.slides)[start:end]` 或 `enumerate(prs.slides)`，不要直接对该集合切片。

### 4.4 硬约束
- 首页和尾页使用原始首页背景，正文使用原始正文背景，不重画近似背景，不叠加第二套标题栏、Logo 或页码。
- 正文标题只出现在顶部标题栏内，白色粗体，不在白色内容区重复；正文首排从 y=0.84 开始，不得上移。
- 每页只讲一个核心结论；每页最多 5 个一级要点、4 张主要卡片，或 1 个主图表加 2 个辅助结论；卡片正文不超过 45 个汉字。
- 同组组件统一圆角、等宽等高；每组最多 1 个强调对象（红色或蓝底）。标题栏、色带、表格网格和分隔线用矩形。
- 图表标明单位、时间范围和来源；饼图和环形图不超过 5 类；不用 3D 图表。图片裁切填充，不拉伸，不放大低清图。
- 正文不得整页栅格化为图片；交付前清除模板英文样例和制作说明（构建报告和检查脚本都会提示残留）。
- 不改变事实或数据的含义；来源之间存在影响结论的矛盾时，明确标出，不自行猜测。

### 4.5 改版与续改
先读 [editing.md](editing.md)。必须保留用户要求保留的事实、数据含义、备注和对象；局部修改不得影响其他页面。
如果所用工具可能丢失动画、备注或图表数据，要在动手前说明，并选择更可靠的路径。

### 4.6 质检（不能为了提速跳过）
1. `python scripts/check_deck.py <deck.pptx>`：检查结构、密度、字号下限、圆角和模板残留，必须没有 error，warning 要逐条处理。
2. `python scripts/office/render_visual.py --pptx <deck.pptx> --output-dir <dir> --json <evidence.json>`：渲染出 PNG。
3. **逐页查看 PNG**，按 [quality-checklist.md](references/quality-checklist.md) 核对溢出、遮挡、换行、对齐和密度；只返修不通过的页面，返修后重新渲染。
4. 全部页面通过后，执行 `render_visual.py --attest <evidence.json> --reviewed-pages all --review-notes "<逐页检查要点与修复>"`。
5. 可选：执行 `check_deck.py <deck.pptx> --visual-evidence <evidence.json>`，若哈希与页数匹配，会标记为 `LIBREOFFICE_PASS`。

### 4.7 交付
提供实际生成的 `.pptx`，并简要说明：页数与结构、采用的模板页和配方、需要用户补充或复核的事项、实际执行过的检查及其结果、尚未执行的检查。

## 5. 验证与汇报诚实性（唯一出处）
- 只报告实际执行过的检查。没有渲染器时写明“未执行视觉质检”，不得写“全部通过”。
- XML 可解析、python-pptx 能打开、LibreOffice 渲染通过，都**不等于**已在 PowerPoint 或 WPS 中实测。
- 结构检查不能证明文字没有溢出、页面美观或数据真实；`--attest` 只能在逐页看过 PNG 之后执行。
- 不得声称已上传、安装、发布或完成任何没有实际执行的操作。
